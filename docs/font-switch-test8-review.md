# Test8：按实际字体归档替换，并修复大字库生成耗时

Test7 在用户手机上仍因组合预提交 120 秒失败，本次不能据主机测试声称已经完成所有机型实测。
此版本修改模块与 App，使用独立的 `io.github.xgl34222220.luoshu.preview`（桌面名“洛书测试版”）。
旧测试 App 的签名私钥不可恢复，新包可并行安装，不要求卸载旧 App；字体库与模块配置仍由模块管理。
后续 preview 构建必须显式使用同一持久化签名密钥，私钥不进入仓库或模块。

## 检测与可替换清单

- 扫描器第 11 版按 SFNT 文件头遍历可信系统分区，不再用文件后缀和固定字体目录名单排除文件。
  配置引用、嵌套路径、没有扩展名的字体均保留；逐面读取 cmap、真实字重、可变轴及命名实例。
- 中、英、数能力按文件内实际字符判断，少量汉字、部分字母、纯数字、全角数字均可成为源。
  不再要求完整字母表、完整十个数字、指定汉字或大于 4 KB。
- 存档的码点范围与原厂完整文件、cmap、码点摘要绑定；换字体复用本机清单和已校验原厂源，
  不在每个槽位重复解码同一大字库。
- 覆盖页的可替换数来自系统文件本身的中英数能力。当前源缺字重或字形时仍列出未完成原因，
  不把原先 15 个可替换槽位变成 11 个。生成、待重启、实际可见文件验证分别报告。
- 主题动态路径、APEX 容器、无法读取或挂载的路径也进入列表，并保留原因；它们不会假报静态挂载成功。
  图标、彩色表情、非目标专用字体保持原厂。

## 导入、组合与字重

导入统一按实际内容识别 TTF、OTF、TTC、OTC、WOFF、WOFF2 及 ZIP/字体模块。
集合逐面导入，保留不同家族、字重、斜体、变量轴；嵌套同名文件不会互相覆盖，模块脚本不会执行。
WOFF2 使用随包分发的 Android ARM64 Brotli 解码器，已经通过 QEMU 执行真实 Android 二进制，
验证解压后的轮廓、advance 及实际导入结果。

组合源不再依赖中文基底预先包含 A–Z、a–z、0–9。缺少的真实英数字形会加入基底；
未提供的字符保留，静态导入字形不会继承旧字形的 HVAR/VVAR 变化量而产生偏移。
新增 TTF、CFF、CID 和可变基底的稀疏字符回归，验证轮廓、GID、FDSelect 与度量。
对已经占满 65,535 字形的基底，继续替换已有字符；无法追加的新字符逐项记录到
`glyphCapacitySkipped`，不会挤掉布局引用字形或导致整个组合失败。某一角色没有任何实际替换时仍失败。

自动字重读取本机归档中的实际需求，支持 550 等非整百字重，不固定生成九份。
固定角色在一个组合请求内只实例化一次。同一请求的源准备、库存生成与提交各有唯一所有者。
真正提交前不改活动字体与重启标记，失败保留原字体、原待重启负载和配置。
并发回收旧 mkdir 锁存在 ABA 窗口，现由持久 inode 的 fcntl 内核锁串行保护事务；
父监督进程被杀后事务子进程仍持有锁，派生的后台生成与 finalize worker 不继承该锁。
recover 在正在提交时返回忙，不删除活跃暂存目录。确定性竞争、父进程被杀及 FD 泄漏均有回归。

普通 glyf 可变源补齐保留真实 fvar/avar/STAT/gvar/HVAR 等变化；新加原厂补集字形使用静态映射。
100/400/700/900 字重分别核对源轮廓及 advance，并核对保留的 Greek/Arabic 排版。
复杂变量 CFF2、VARC、布局变化表等未可靠支持的结构仍明确失败，不伪造可变能力。

## 性能证据

同一主机、同一官方 Noto Sans CJK 16.4 MB 字体，144 路径、24 个不同原厂度量合同，
使用包内 FontTools 4.63.0；准备原厂测试数据不计入生成时间。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 完整库存映射 | 52.70 秒 | 10.77 秒 |
| 峰值 RSS | 741,740 KiB | 524,408 KiB |
| 映射路径 | 144 | 144 |
| 生成不同度量字体 | 24 | 24 |

优化保留原 CFF 子程序字节，避免整库解释重编；近全集裁切优先裁 cmap，只有字形数量超限时才做闭包子集。
同源/同合同复用生成结果，原厂码点与度量读取缓存复用。所有 44,810 个编码字形轮廓与 advance 一致，
修改前的 65,393 个字形轮廓均保留；HarfBuzz 中文、Greek、假名、韩文、罗马数字及部首排版一致。
已生成缓存恢复耗时 0.086 秒，144 个文件完整摘要一致，恢复过程没有再生成字体。
这是开发环境基准，不包含手机重启，也不是用户设备的最终换字时长承诺。
另测 49k 字形的大 TTF→CFF 跨格式转换，首次从 80.32 降至 65.62 秒，
同一运行内复用转换缓存从 35.88 降至 6.95 秒。所有字体表除 head 时间及对应校验和外逐字节一致。
转换逐字形编译并释放坐标，避免同时保留整库 Python 指令和展开坐标；
这条首次大规模转换仍可能超过一分钟，不能宣传所有字体秒换。

另以真实 fixed 组合源、库存引擎、监督器和原子提交运行核心全流程：相同 Noto 中文、
DejaVu 英数、144 路径/24 度量，首次 14.403 秒，峰值约 555.3 MiB，144/144 映射且零失败。
再次请求 13.417 秒，其中只有复合源命中缓存（0.180 秒），库存仍重新生成（13.237 秒）；
不能称整流程秒换。此测试预置本机清单，未计入导入、刷写扫描、界面等待及手机重启。

预提交现在显示真实已处理文件、总数和耗时；只有处理进度和进程 CPU 活动持续停滞才按 120 秒终止，
仍保留 600 秒总上限及完整子进程取消。上述性能优化与超时监督分开验证。
