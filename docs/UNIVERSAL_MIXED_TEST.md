# Universal 复合字体接入测试说明（2026-09-30）

此改动基于 main `0388b57`，独立于 `fix/universal-cutover-visible-takeover`。
它是实验性源代码改动，不是正式版或全 ROM 验证结论；不更新版本号、发布标签或更新源。

## 接入范围

- 保留原 CJK / Latin / Digit 角色合成、TTC 选面、用户轴值和固定 / 自动字重选择
- 固定组合：用通过原合成校验的完整输出，进入真实 SourceProfile → FontPlan → XML 路由 → Compiler → Gate → Deployment
- 自动九档组合：对九份实际合成结果做严格兼容性检查，构建具有实际 `gvar` 轮廓增量的 `wght=100…900` 可变完整复合字体
- 中文固定而英文 / 数字可变时，中文保持不变，英文 / 数字按已有九档的真实轮廓变化
- 记录实际组件实例轴坐标；动态源轴若发生截断或未知选定轴被忽略，不把它宣称为完整可变覆盖
- 冻结源至私有目录后再编译，不依赖工作目录留存；失败清理大字体副本，保留最多三次诊断记录
- 下一启动身份始终是 `mix`，并保存 requestId / deploymentId / payloadDigest；最终提交和重启后的状态不能误认另一代组合
- Universal 成功后，旧的 ROM 别名补全和 legacy finalizer 不得再次覆盖新负载或引擎标记
- 当前启动字体负载不动；完整重启激活仍由原 Universal 启动事务负责

## 明确不支持 / 会安全回退的情况

- 全部主文件轮廓相同，仅改字重名称，不能称为真实 VF
- 自动主文件的轮廓类型、字形顺序、cmap、轮廓点结构、组件或布局表不兼容
- 当前 VF 装配器只处理兼容 glyf 主文件；CFF/CFF2 主文件不强行变成 glyf VF
- 原组件动态轴范围不足、目标额外要求其他可变轴或目标 wght 范围超出生成范围
- 普通静态源不能冒充多个真实字重或纯物理 VF 槽；已验证的固定组合可使用下述显式 fixed-stock-shell 契约
- 目标自然几何超出 Universal 已有对齐阈值；没有降低门槛、强行平移或篡改 stock 证据
- 资源预算不足：九份大体积 CJK 主文件可能触发保守内存门，仍走兼容路径，不保证每台手机可完成 VF 装配
- 源分析、设备拓扑、角色映射、编译验证、部署完整性任一不通过

回退保留原兼容行为，但应通过 cutover 状态和日志看到原因；“任务成功”不等于 Universal 已接管。
图标、Emoji、受保护角色的安全门保持不变。并未将物理 VF 标成静态文件来绕过校验。

## 验证边界

新增测试使用可辨认字形的自造字体，避免商业字体、ROM 字体及用户私有文件。
覆盖真实完整编译 / 安全门 / 部署链、角色轮廓、保护槽、来源删除、摘要篡改、请求失效、多次提交和重启状态。
VF 单元测试验证九档主字重和中间字重的实际轮廓及 advance。

这些是宿主合成字体和 shell 测试，不代表花轮丸 / 鸿蒙保时捷 VF 已实测，也不代表任何 ColorOS / HyperOS 真机已无偏移。
当前工作环境缺少 Android SDK / Gradle / ARM64 嵌入式 runtime，完整模块构建需仓库测试 CI 或具备这些工具的环境。
完整 `check.sh` 在缺失 runtime 清单处停止时，不能标成全通过。没有产生可刷 ZIP 时，补丁 / 源码 ZIP 不能用于刷机。

## 真机验收建议

1. 先保存当前工作配置，并确认测试包提交号与构建产物摘要
2. 在组合页重新应用指定三个角色及轴 / 固定自动设置；保存日志和 cutover / next 状态
3. 只有 `pipeline=universal` 且新的 deploymentId / payloadDigest 验证通过，才算进入新链路
4. 完整重启后查看 Universal runtime verification，记录启动身份及回退原因
5. 对比桌面、状态栏、设置、锁屏时钟、常用应用的中英数字；检查各字重、行高、基线、裁切、时钟 advance，以及图标 / Emoji 保持原样
6. 不通过时使用既有回滚 / 系统默认路径；保留可复现的截图和日志，不能仅凭 UI 的“已应用”推断成功

## 长时间99%反馈后的修正

已确认旧固定组合进度在文件合成结束时达100%，外层映射成99%，但后续Universal处理没有接入同一进度；它不能区分长编译和死亡的子进程。新增请求绑定的阶段/槽计数，文件合成最多到76%，最终提交单独显示97%。

确定无法满足的整批计划，在编译任何槽前拒绝；并保留对集合字体、专用数字/时钟和固定轴stock-shell的有效例外。只读stock/output探针改为lazy读取，实际修改字体的路径保持原行为。

宿主可复现测量：20,112字形、每字64点、4.18MB TTF，20个有效静态槽的编译113.0秒降至72.9秒，峰值RSS230.3降至149.9MiB；所有输出摘要、报告和manifestId相同。20静态槽加1个不可能接受静态源的物理VF槽，完整Shell准备115.9秒降至0.8秒、零无用编译输出。这些数据不是手机实测，也不能单独证明用户当前卡住的唯一原因。

兼容运行时现在接入已有进程范围管理，嵌套worker有任务/PID身份。Universal准备阶段180秒上限，外层混合任务660秒总上限，均先回收子进程；外层720秒App观察期限不再短于正常任务范围。取消记录绑定request，并由开机激活再次检查，防止迟到负载被应用。失败/结束会保留日志；已提交的同代负载在期限边界按完成处理。

新增模拟崩溃/延迟/finalizer/取消回归与读取等价回归，仍需用户日志确认设备侧阶段，再检查真机覆盖和偏移。


## 固定组合与逐路由契约修正

- 语言标签按 BCP47 主语言和脚本解析，不能把 Ital / Plrd / Rohg 当作 it / pl / ro。明确的其他文字、图标、Emoji、cursive / casual / fantasy 独立家族保留原厂
- 同一物理文件的正常、斜体、不同 wght / ital / slnt XML 引用分别选择来源并验证；单个斜体引用不能污染全部正常引用
- 固定组合报告绑定 requestId、实际合成文件 SHA256、各角色固定选择。请求轴与实际有效轴分开记录，静态字体不会被假称拥有变量轴
- 仅该显式契约可以使用原厂容器固定替换选中字形：保持 OEM fvar / 非目标字形 / 原生布局，清除导入字形的 gvar 与 HVAR / VVAR 映射。源400不重命名成其他真实字重，目标容器仍保留原厂元数据。选择的字形不再随 OEM wght / wdth / ital / slnt 改变，这是固定选择语义
- 不支持的真正斜体 XML 引用保留原始文件与节点，并记录 preservedRoutes；状态显示“部分覆盖”。保留原厂布局意味着某些非 cmap 连字（例如 GSUB 的 fi）仍可能使用原厂轮廓，不能称全字形覆盖
- 稀有汉字子集缺少默认探针时，按实际共有 Han 字形选取最多64个确定性探针，至少4个有轮廓；规划、重开验证及启动检查使用同一组。不能拿拉丁/符号或空探针替代 CJK 验证
- 固定原厂容器拒绝 VARC；保留 MVAR 时按各变化区域最大可能贡献检查导入轮廓的保守行框预算。该检查不等于各应用渲染实测
- 编译失败会记录逐槽 reason 和异常函数/行号，诊断导出可读取现有失败记录，不必重复生成字体

测试使用自造字体。修正与宿主回归不证明实际商业字体、ColorOS 界面或完整变体范围已通过真机验收。若仍有不安全几何或不支持契约，继续明确回退。

测试 APK 的临时签名可能不同，不能要求卸载旧 App。本轮使用独立 `.audit` 包名和“洛书·核心验收测试”名称，需手动选择并排安装；模块不自动安装/替换它。旧 App 与其私有预设/队列保留，新 App 私有设置不自动迁移，字体目录和模块共用。


## 全面审计修复后的边界

详见 `UNIVERSAL_AUDIT_REMEDIATION.md`。本轮增加变化区间/重开验证、独立hint环境、复合及共享字形依赖隔离、GSUB闭包和GPOS定位一致性；真实DejaVu/Noto通过不同探针缩放后的宿主RAQM验证。MATH构造字形和跨文字共享标记可明确保留，计入部分覆盖。原厂容器保留原生非cmap替换布局，不能把原厂fi等连字称为已换成用户轮廓。

VARC、点匹配可变复合字形、source-variable-preserve CFF2、无法安全隔离的CFF1 seac依赖、未支持的AAT/BASE/变体定位设备及歧义布局会明确拒绝。普通CFF、可证明的glyf变体和静态路径仍有正例。动态多面/不完整权威配置/无法取得原始未覆盖字节仍有安全限制。以上不等于所有ROM、所有字库、所有应用的全覆盖认证。
