# 字体任务进程生命周期

正式版字体任务由一个有限的任务监督进程运行。它只在本次任务存在时工作，任务结束后退出；没有新增常驻监控服务。

- 每次任务记录启动周期、PID、进程启动时间和随机作用域标识。缺少身份信息的旧 PID 不会被当作清理授权。
- 成功、失败、超时和取消都会结束并回收本次任务的子孙进程，包括脱离原父进程或另建 session 的工作进程。不会按进程名、`ps | grep` 或全局进程组批量杀进程。
- Linux subreaper 收养孤儿进程，回收时使用 pidfd 固定进程身份。没有 pidfd 的旧内核只允许监督器结束自己尚未回收的直接子进程，再逐层收养并清理后代，避免 PID 复用误杀。
- 取消通过本次作用域的随机标识请求，工作目录使用独占的 `cache/tasks/<token>`。只删除带本次所有权标记的任务目录，不扫描清空整个缓存，也不清理挂载负载目录。
- 固定字重复合字体需等待原提交监控完成下一启动负载提交，才结束本次任务作用域。提交沿用整项任务剩余时限，不另加较短等待窗口。监督器默认整项时限为 900 秒，可配置为 1–3600 秒；前台切换仍保留自身 30–900 秒限制。可选的切换后后台预热已停用。
- 脱离终端只使用 session 隔离。任务监督器不创建挂载命名空间、不调用 `unshare`，不改变原有挂载和负载提交实现。

## 边界

内核 `SIGKILL` 无法执行任何退出处理。如果监督器本身被强制杀死，不承诺立即自动清理：下次启动、取消或任务状态恢复操作会尝试根据保存身份和作用域回收残留。若旧内核不支持 pidfd，无法安全结束已被系统接管的残留进程时会保留恢复信息并拒绝覆盖任务；完整重启可结束这些进程。

内核不可中断的 I/O 状态也可能延迟 `SIGKILL`。此时保留身份和任务目录，并显示尚待内核 I/O 的失败状态，不宣称已经清理完成。

主机测试通过不等于设备验收。正式 ARM64 Python、`prctl`、pidfd 和 Android `/proc` 行为仍应由 Android Root 测试确认。

## 错误消息读取

`task_scope.py error-message PATH` 读取已完成输出文件的有界尾部，保留最后一个有效顶层字符串消息。`error-message-stdin` 为已经完成、由调用方捕获的扫描输出提供同一解码逻辑；调用方通过独立管道写入这些文本并关闭管道。它不读取 App 请求监督器的开放 stdin 租约，不创建或接管任务。

管道每次读 64 KiB，仅保留最后 256 KiB；被截断的首条记录不被解释为完整响应，消息上限 4096 字符并清理控制字符。原厂扫描错误复用此入口，没有新增临时文件或常驻进程。原文件入口没有将字面路径 `-` 改成 stdin。
