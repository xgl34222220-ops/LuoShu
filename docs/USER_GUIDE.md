# 洛书完整使用教程

本文说明洛书 v2.3.x 的下载、刷入、App 安装、字体导入、单字体应用、组合字体、恢复、卸载和故障排查。

## 1. 下载正确文件

只从仓库的 [Latest Release](https://github.com/xgl34222220-ops/LuoShu/releases/latest) 下载正式版。

正式 Release 包含：

```text
LuoShu-<版本>.zip              模块包，内置正式 App
LuoShu-<版本>.zip.sha256       模块校验文件
LuoShu-App-<版本>.apk          独立正式 App
LuoShu-App-<版本>.apk.sha256   App 校验文件
```

模块包和独立 APK 使用同一把固定签名。旧 Debug App 与正式 App 签名不同，Android 拒绝覆盖时，请先卸载旧 Debug App。

## 2. 刷入模块

1. 打开当前使用的 Magisk、KernelSU、SukiSU Ultra 或 APatch 管理器。
2. 选择 `LuoShu-<版本>.zip`。
3. 等待刷写完成。
4. 完整重启设备。

洛书不需要额外安装任何元模块，也不需要加入白名单或修改其他挂载模块配置。刷入日志中应显示：

```text
✓ 挂载：洛书私有自挂载
✓ 私有字体负载已部署
✓ 洛书将独立完成字体挂载
```

刷入阶段会部署文件、扫描本机原厂字体配置并迁移旧字体状态，但不会在安装脚本中生成大型复合字体。

## 3. v2.3.x 私有自挂载

真实字体负载保存于：

```text
/data/adb/modules/LuoShu/.luoshu-payload/
```

标准模块分区目录保持为空，其他挂载组件无法重复接管洛书负载。洛书根据 Root 环境自行完成挂载：

- KernelSU / SukiSU Ultra / APatch：在 `post-mount` 阶段挂载；
- Magisk：在 `post-fs-data` 阶段挂载。

无需选择 OverlayFS、Magic Mount、Kasumi 或其他后端。洛书不会修改 Mountify、Hybrid Mount、Magic Mount 等外部组件的配置。

App 首页根据当前字体事务和自挂载状态显示“当前生效”。配置尚未完成、仍需重启或自挂载失败时会明确显示等待或异常；正常开机不再自动遍历、哈希完整字体树，也不会启动 Python 深度验证。深度加载检查仅在手动诊断时运行。

## 4. 安装或更新 App

模块包始终内置原生洛书 App：

- 在 Root 管理器中点击洛书模块的“操作”按钮；
- 或直接安装 Release 中的 `LuoShu-App-<版本>.apk`。

刷写环境能调用 Android 包管理器时，模块会自动覆盖更新 App；否则在首次完整开机后补装。仍失败时使用模块“操作”按钮重试。

## 5. 准备和导入字体

支持常见 TTF、OTF、TTC、TrueType `glyf`、CFF、CFF2 和可变字体。

推荐直接在 App 中使用系统文件选择器。也可以复制到：

```text
/sdcard/LuoShu/fonts/
```

待提取的字体模块 ZIP 可放入：

```text
/sdcard/LuoShu/import/
```

洛书只提取字体文件，不执行第三方模块脚本。

### 字体角色要求

中文基底应包含常用中文、英文字母、数字和常用标点；英文字体应包含 `A–Z`、`a–z`；数字字体应包含 `0–9`。图标字体、彩色字体、损坏文件、伪装扩展名和缺少关键字符的字体会被拦截。

## 6. 扫描字体库

1. 打开洛书 App。
2. 进入“字体库”。
3. 点击扫描或刷新。
4. 等待字体名称、格式、字重、可变轴和覆盖能力分析完成。

字体内容和修改时间没有变化时，洛书会复用缓存。

## 7. 直接应用单个字体

中文、英文和数字三个槽位选择同一字体和同一标准字重，然后点击生成并应用。满足快速路径条件时，不进行不必要的多次大型合成。

## 8. 生成组合字体

1. 选择中文字体。
2. 选择英文字体。
3. 选择数字字体。
4. 选择字重或可变轴。
5. 检查预览。
6. 点击“生成并应用复合字体”。
7. 等待任务达到 100%。
8. 完整重启设备。

组合字体以中文字体作为完整基底，只写入英文和数字负责的目标字符，不依赖系统缺字回退拼接三套字体。

## 9. 字重与可变字体

静态字体只显示真实存在的字重；静态多字重字体默认只生成当前选择的字重。可变字体读取真实 `wght`、`wdth`、`opsz`、`slnt` 等设计轴和范围。

## 10. 为什么必须完整重启

Android 的字体缓存、应用进程和系统服务不会同时安全热刷新。洛书不会通过只重启 SystemUI 宣称字体完整生效。

生成并应用完成后请完整重启。同一次开机内建议只提交一次系统文字字体变更。

## 11. 设备自适应原厂字体清单

安装时洛书会扫描当前设备真实字体结构，而不是根据手机品牌套用固定文件清单。常见扫描范围：

```text
/system
/system_ext
/product
/my_product
/vendor
/odm
/oem
/my_region
/hw_product
```

扫描器会解析实际存在的 `fonts.xml`、`font_fallback.xml`、`fonts_customization.xml`，记录真实路径、分区、family、alias、字重、样式、TTC index 和字体度量。应用时优先使用当前设备清单；只有清单无效或没有发现槽位时才进入静态 ROM/AOSP 回退。

ColorOS、HyperOS 等名称只表示已有真机验证与额外回退，不是 ROM 白名单。

## 12. 恢复系统字体

1. 在 App 中选择“恢复系统字体”。
2. 等待任务完成。
3. 完整重启设备。
4. 确认系统字体恢复正常。

恢复失败时先查看日志，不要连续反复提交任务。

## 13. 卸载模块

1. 建议先在 App 中恢复系统字体。
2. 完整重启。
3. 在 Root 管理器中卸载洛书。
4. 再次完整重启。
5. 需要时单独卸载洛书 App。

卸载脚本会逆序解除洛书记载的挂载，清理 `.luoshu-payload` 与洛书状态文件，不删除 `/sdcard/LuoShu/fonts/` 中的用户字体。

## 14. 常见问题

### ROM 不在测试列表

仍会执行完整本机扫描和设备清单映射。测试矩阵只表示维护者是否完成整套真机回归。

### 安装了其他挂载类模块怎么办

无需配置。v2.3.0 的标准分区目录是空壳，真实负载位于私有目录并由洛书自己挂载。不要把洛书手动加入其他模块白名单，也不要为洛书修改外部挂载配置。

### 组合任务很慢

大型 CJK、CFF/CFF2、TTC 或复杂可变字体需要更多处理时间。相同组合再次生成时优先使用缓存。

### 显示“字体组合失败”

常见原因包括字体损坏、关键字形缺失、格式伪装、存储空间不足、内存不足或后台任务被系统终止。请同时导出日志和诊断报告。

### 部分应用文字没有变化

应用自带字体、输入法键帽、图片文字、游戏私有引擎、网页下载字体和部分 WebView 通常不经过 Android 系统字体映射。

### 需要手动深度检查字体加载

正常使用不需要运行深度验证。只有在字体显示异常、挂载状态与实际效果不一致或需要提交诊断报告时，才执行：

```sh
su -c 'sh /data/adb/modules/LuoShu/common/device_font_load_verify.sh verify'
```

该命令会读取 FontManager 状态并检查可见字体证据，运行期间可能产生短时 CPU 和存储读取。

### 卡在开机二屏

先停用或卸载刚安装的其他字体模块，再测试洛书。v2.3.0 不会让元模块挂载洛书；若仍卡二屏，请在安全模式或 Root 管理器救砖环境中禁用洛书，并提交以下文件：

```text
/data/adb/modules/LuoShu/logs/self-mount.log
/data/adb/modules/LuoShu/config/self-mount.conf
/data/adb/luoshu/self-mount/mounts.list
```

## 15. 安全与授权

洛书不直接修改只读系统分区，不执行导入 ZIP 中的脚本，输出字体验证通过后才提交。请勿上传或分发没有授权的商业字体；分享日志和报告前请检查隐私信息。
