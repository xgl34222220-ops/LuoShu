# Test5：按本机实际字体清单完成替换

> 后续真机反馈和回归已确认 Test5 存在补齐缩减覆盖、跨脚本整文件跳过及启动验证误报。
> 本文是历史记录，不代表这些路径已经正确；修复与重新验证见 [Test6](font-switch-test6-review.md)。

## 问题与修复范围

Test4 虽然有通用扫描，实际切换、组合预提交、开机补槽与部分旧 API 仍依赖 ROM 映射。
这会导致扫描数量、实际输出和“补齐”判断不一致。Test5 将这些生产入口统一为
`stock_inventory_scan.py → inventory_font_stage.sh → inventory_font_stage.py`。
旧 ROM 文件仅保留历史兼容和独立回归；当前生成流程不根据品牌、机型或 ROM 名称选替换目标。
旧主题挂载日志只做升级恢复，不再用于生成新的主题字体。

## 检测与替换

- 扫描版本 9、度量版本 4。读取可信原厂分区里的实际字体，以及字体 XML 引用。
- 支持未知分区、嵌套目录、非标准文件名、XML 引用的非标准后缀、旧版 XML、多字体集合和可变轴。
- 记录每个物理文件、每个集合面的真实字符脚本、数字、样式、字重与原厂布局度量。
- 普通字体、组合字体与补齐都使用同一份清单。当前选择的源字体优先；同族真实字重和样式仅补足其缺项。
- 多面集合保持完整索引与面数；缺少某个必需字体面时整体保留，不能用单面字体冒充集合。
- 字符、样式或字重不足时记录原因并保留原厂；不再将这些项目列为反复点击即可解决的“待补齐”。
- 按原厂 head/hhea/OS/2 合同生成度量，保留源轮廓。只有 XML 和实际字形覆盖证明存在中文后备时才裁去 Latin 槽的中文映射。
- 动态字体链接按库存来源、当前真实目标与字体内容处理，生成隔离视图；不修改原文件与系统链接。
- 暂存、缓存验收、提交、挂载和恢复默认均支持扫描得到的嵌套目录。

“检测到的文本文件数”和“当前选中字体能完整替换的文件数”分别计算。
例如系统槽包含 Latin、Greek、Cyrillic，而用户字体没有后两者时，该槽仍保留在扫描清单中，但不会丢弃原有语言字形后强行替换。
添加同族且满足所需脚本的源文件后，无需缩减或重扫库存即可恢复该槽覆盖。
Emoji、彩色字体、图标、纯符号及损坏字体有明确保留原因。

## 性能与隐藏问题

- 相同源与度量合同只生成一次，其他目标复用成品；不逐个重新编译大字体轮廓。
- 缓存身份包含库存、生成器、选中源及同目录候选源的变化。旧生成器缓存失效，当前已生效负载保留。
- 增量修复验证源锚点、库存与输出摘要；损坏或来源不明的现有文件不算已覆盖。
- 修复自动组合子函数污染外层字重、角色、字体名与路径变量的问题。
- 修复仅嵌套字体目录成功时仍回滚、恢复默认漏清任意目录、卸载缺少日志目录时提前退出的问题。
- 修复读取自身动态挂载后将旧源额外脚本误当原厂要求的问题。
- 缺失核心组件明确报错；不回退旧 ROM 映射。删除当前字体和旧异步接口走同一暂存提交流程。
