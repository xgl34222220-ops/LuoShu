# Test3：检测、刷写、偏移和切换回归

本次在 PR #249 的 Test2 上继续修复。模块和 App 版本号保持不变；测试模块沿用
Test1/Test2 的同一份 Debug APK，避免更换测试签名。没有加入用户字体或 ROM 字体。

## 行为变化

- 刷写输出按环境、原厂检测、App、挂载部署四个实际阶段组织。部署成功后才显示
  完成，扫描待重试、App 签名冲突、校验失败和临时安装失败分别说明。包管理查询
  超时后直接安排开机补装，不在刷写页连续等待多个包管理调用。
- 扫描器升级为 v7。跨分区 XML 的 UI alias 链可找到未知 OEM 家族；保留来源分区、
  字重和 TTC 字体面。损坏字体单独排除；同实体文件只读一次；同 ROM 有效结果复用
  时不再做全分区普查。未知 ROM 的回退按字符覆盖、真实字重及字体类型判断，避免
  把专用语言、符号、彩色、等宽或斜体字体泛化替换。
- 原厂扫描接受的零下伸时钟合约现在可以完整传到补齐器。目标槽合约缺失时不会
  偷换为主字体合约；缺少可信合约仍使用明确的通用回退。
- HyperOS 原厂 Latin UI 槽补充 Noto 字体变体判断，修复 SemiCondensed 名称误判。
  收紧底部留白前检查保留字形及 GSUB 替代字形，无法证明安全时保留原厂框。
  不平移时钟或主字体的字形基线，不用替换整份系统 XML 来修偏移。
- HyperOS 标点差异只需对同一个大字库生成一次共同子集，再逐槽调整字符映射。
  通用补齐只编译改过的度量表，字形、cmap、hmtx 等原始表不再重复编译；探针按源复用。
- ROM 暂存阶段明确保留的动态别名、专用字库、缺真实字重槽位，不会在随后通用
  补齐时被重新创建。覆盖页面将其列为保留，避免反复出现不可修复的补齐项。
- 同秒组合请求有独立标识；旧任务不能提交新暂存目录或改写新任务状态。重复点击
  不能删除正在生成的组合目录或启动中的补齐计划。取消、失败会释放提交锁。
- 缓存升级为 v5，增加整个暂存树的路径/大小校验；缺 OEM 分区、截断文件、源文件
  同秒变化会使缓存失效。校验不反复哈希每个大字体别名。

## 可复现验证

完整入口为 `sh scripts/check.sh`；`sh scripts/build.sh` 会再次执行它。新增及扩展测试
覆盖真实 TTF、CFF、CFF2、TTC、可变字体、FreeType 排版、未知厂商表、SFNT 校验和、
跨分区 XML/符号链接、坏字体隔离、并发提交、取消恢复、缓存损坏及 ROM→通用补齐串联。
原有 ColorOS、OriginOS/Flyme、挂载和更新保留测试继续执行。

大字库使用公开的 Noto Sans CJK SC Regular：16,437,364 字节、65,535 字形，
仅保存在工作区作验证，不随模块交付。下面都是宿主机测量，不是手机换字体承诺：

| 阶段 | 测试规模 | Test2 | Test3 |
| --- | --- | ---: | ---: |
| 通用逐槽度量批处理 | 144 槽、24 合约 | 11.18 秒 | 5.04 秒 |
| 实际组合预提交入口→通用补齐→原子提交 | 同上，bundled FontTools 4.63.0 | 12.23 秒 | 6.46 秒 |
| HyperOS 暂存度量及 CJK 路由 | 49 槽、25 合约、4 种标点集合 | 28.18 秒 | 8.94 秒 |
| 扫描度量读取 | 同实体字体的 48 个路径 | 3.14 秒 | 0.08 秒 |

Test3 的四目录、144 槽缓存校验与恢复约 0.05 秒；这是缓存环节，未包含完整前台
切换。通用预提交验证了原始 CFF 字节、每槽行度量、下一启动状态及当前负载不被修改。
HyperOS 验证了主 MiSans 字形不变、逐槽度量及标点/汉字路由。

## 真机验证边界与回退

支持多 ROM 布局和未知 OEM 的安全发现，不等于验证过所有机型。没有本次 Redmi
HyperOS 的实际源字体、完整失败日志或刷入结果；QQ 标签、锁屏、Chrome/Google
界面仍需真机核对。首次复杂组合、低速存储及字体自身异常仍可能增加耗时。

刷入后完整重启，再应用字体并重启验证。生成或补齐失败不会改当前已挂载字体；
可在 App 选择系统默认字体后重启，也可在 Root 管理器停用模块后重启。
