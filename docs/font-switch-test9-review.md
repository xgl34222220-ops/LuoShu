# Test9：修复多面 CJK 集合生成失败与重复工作

Test8 在用户手机上先显示 `365/849，已用 385 秒`，随后达到 600 秒总时限并失败。
该反馈证明之前的单面 CFF 主机基准不能代表本机多面 TTC 的生成链路。
本次保持 600 秒监督上限，直接修复生成和复用问题；没有连接用户手机。

## 已定位的问题

- `849` 是 283 个槽位的三轮内部工作计数，并非 849 个字体文件。
  进度改为当前阶段真实文件数，并显示当前集合的字体面及阶段耗时。
- 实际 Noto Sans CJK 集合有十个字体面。共享的原厂 CFF/度量表可以复用校验，
  但不同地区的 cmap、异体字和不同字体面的度量不能被一个输出面覆盖。
- 相同面序列的集合过去按每个逻辑路径反复装配，现在只装配、验证一次，仍保留全部路径。
- 选中 TTF 转 CFF 后，又为计算垂直原点完整解释一遍转换字形；转换结果与垂直合同应分别复用。
  原来的完整源缓存只校验原厂垂直度量表，遗漏了把码点映射到垂直字形所需的 cmap。
- 同一组合在新请求中没有复用最终库存生成结果，只复用了前面的组合源。
- 转换缓存命中后仍重复执行大型 CFF 子集解释；现在只有相同来源、替换范围及子集证明才能跳过重复工作。
- 各地区字体面重复保存约 66 MB 的相同轮廓。对原厂轮廓和度量合同相同的集合，
  统一未编码的保留字形顺序，使集合共享轮廓表；每个字体面的字符映射和布局表继续独立。
  合并后的字形数量超限时不使用共享方案，不删除字符来凑容量。

## 字形容量边界

实际日文字体面和大字库源合并时，原厂保留闭包 45,039 字形、源闭包 48,965 字形，
合计 94,004，超过单个 OpenType 字体的 65,535 字形上限。
这不是延长超时能够解决的问题。

容量不足时，对已经选择替换的字符，如果所选字体没有对应异体字序列，使用所选字体的常规字形，
逐项记录该回退；保留全部原始字符编码及异体字序列编码。
未选择替换的字符及其异体字继续保留原厂形状，源字体已有的异体字继续使用源形状。
不能将此行为描述为所有原厂异体字形状不变。

按最终 stage 的中、英、数替换范围重算，测试集合需要 16,507 个原厂保留字形和
48,913 个源字形，共 65,420 个，低于上限。保留字形并集只增加未编码字形以统一顺序；
这些字形不会作为新的布局闭包入口，也不会改变各地区字符映射。
独立核验全部十个字体面的 448,100 个字符映射和 30,364 个原厂异体字序列：
字符轮廓、横向度量及原厂保留字形的纵向度量没有不符合预期的变化。
