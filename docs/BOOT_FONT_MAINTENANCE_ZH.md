# 启动期字体维护与诊断

## 本轮变化

- 旧物理文件兼容路线的 pre-mount 原厂扫描采用 3 秒工作预算，随后仍需任务监督器确认其子进程清理。此数值不是整部手机的开机耗时，也不跳过主挂载。
- 启动期扫描锁忙、原厂视图不确定、扫描超时或清理未确认时，保留旧清单和待办，不将未完成扫描标成成功。扫描先写独立暂存区，真实任务成功并完成清理后才发布。
- 已挂载或启动完成后，不继承早期“可见原厂字体”标记。正常完整重采继续由原有 lower/mirror/snapshot 安全解析路径处理。
- 冻结 service 自己负责模板检查与后续加载核验，release helper 不再在它之前重复执行同一组维护。直接调用 helper 的原有契约不变。
- 未能取得模板锁不等于模板有效。保留已有模板并明确返回未完成状态。
- 任务页将后台原厂槽位检查与用户字体应用分开显示；等待主命名空间挂载确认不显示成“设备重启已完成”。1970 年早期日志显示为“开机早期，时间未同步”。错误记录仍保留。

## 一次设备证据

若仍有开机慢或模板错误，在“任务与日志”右上角点击“生成脱敏诊断报告”，将保存的 LuoShu-diagnostic-summary.txt 提供给维护者。报告新增 legacy 路线、原厂扫描待办、模板待办原因类别、负载事务状态及启动扫描结果收据；收据明确标注是否属于本次开机。原始 boot ID 和源字体名称不会导出。

Google 应用字体在使用一段时间后恢复默认属于另一条证据链。在 Google 字体兼容页面先保持现场，通过“导出复发诊断”采样组件状态、资源身份与挂载，不先关闭重开兼容。见 [Google 字体兼容说明](GOOGLE_FONT_COMPATIBILITY_ZH.md)。

以上是已定位代码缺口的修正，不代表某一 ColorOS 真机的全部慢启动或字体复发根因已得到确认。冻结的 1.1.1 挂载 core/nohook 保持原样；Android 12 及以上系统启动屏仍由平台控制。
